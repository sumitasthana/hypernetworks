Running UnCLe on Colab

Nine cells, in order. The tasks come from this folder; the hypernetwork, the learn and forget operations and the four metrics come from the uncle package next door.

Setup

Three cells, once per runtime. Runtime → Change runtime type → T4 GPU before you start, otherwise everything below runs on a CPU and the ResNet runs are hopeless.

1Clone and put the folder on the path
Do not pip install -r requirements.txt here. Colab already ships torch, torchvision, numpy, Pillow and matplotlib, and reinstalling torch is the fastest way to get a build that cannot see the GPU. That file is for a local machine.
2Confirm the GPU is really there

Every entry point picks cuda on its own when it is available, so there is nothing to pass. If this prints False, stop and fix the runtime type.

3Mount Drive, so the 240 MB download happens once

Pass root=DATA, download=True the first time. The archive extracts into Drive and every later runtime finds it already there. Leave root out entirely and the data lands inside the cloned repo, which disappears with the runtime.

Example 2: the paper's setting

Thirty requests over twenty tasks, ResNet50 generated in 200 chunks. This is the real run, and it wants hours. output makes it survivable: the history is rewritten to Drive after every single request, so a disconnected runtime costs you the current request, not the run.

5hours
Time it before you trust it. Watch the wall clock between request 0 and request 1, then multiply by thirty. A T4 session has a limit, and if one learn request takes forty minutes the full sequence will not finish inside it. Drop to backbone="resnet18", fewer epochs, or split the sequence with limit_requests.

Example 3: sweeping a parameter

Every Config field passes straight through as a keyword argument, so a sweep is a loop over calls. Nothing is written to disk and nothing is printed, so the loop stays readable.

What the arguments do

ArgumentEffect
sequence1, 2 or 3: which row of the paper's Table 4 to run. Thirty requests each.
limit_requestsStop after the first n. Cutting from the front keeps the list valid, because every forget still follows its learn.
max_imagesCap images per task, spread evenly so all ten classes survive. For checks, not results.
rootWhere the dataset lives. Point it at Drive.
downloadFetch the archive when root is missing. Needs a path ending in tiny-imagenet-200.
outputDirectory for the two JSON files, or None to keep everything in memory.
on_requestCalled with each record as it finishes.
verboseWhether to print the per-request lines.
configA prepared Config, instead of the overrides.
anything elseGoes to Config: backbone, epochs, chunks, batch_size, beta, gamma, burn_in, noise_samples, seed, device.

Reading the four numbers

run_experiment returns (history, numbers). Accuracy at the end hides the two failure modes the paper is about, which is why there are four.

RA
retain_accuracy — average over tasks still held at the end. Higher is better.
FA
forget_accuracy — average over forgotten tasks. Should sit at chance, 10%.
Spill
mean_spill — how much one forget request disturbed every other task. Lower is better.
Relapse
mean_relapse — how much a forgotten task crept back as later tasks were learned. Lower is better.

The paper reports 55.24% retained accuracy on Tiny ImageNet in Table 3, so that is the region to check against. history holds a record per request with before and after accuracy for every task seen so far, plus final_loss and the annealed burn_in that forget request used.

Five things that will bite

  • Memory grows with history. The regularizer regenerates every protected task's weights in one graph, so by request 29 it is holding nineteen full sets of ResNet50 parameters at once. If a late request dies with a CUDA out-of-memory error while early ones were fine, that is why. Fewer chunks, a smaller batch_size, or ResNet18 are the levers.
  • Data loading is single-threaded. The loaders inside uncle/trainer.py use the default of zero workers, so JPEG decoding happens on the main process. At 5,000 images per task it is probably not the bottleneck, but if the GPU looks idle, that is the first place to look.
  • Accuracy here is validation accuracy. Tiny ImageNet's public test split has no labels, so the test slot holds val. Say so when you report a number.
  • Task IDs differ between the two folders. This one shuffles the 200 WordNet IDs with seed 42; uncle/data.py cuts them in sorted blocks. Task 3 is ten different classes in each, so name the partition whenever you compare.
  • A learn is not repeatable. The sequences never learn the same task twice and Config rejects it if you try. Relearning a forgotten task needs a separate adaptation path, which does not exist yet.
