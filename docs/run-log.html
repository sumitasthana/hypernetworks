Sequence 1 on Tiny ImageNet, end to end

The first complete run of this reimplementation at the paper's scale. It finished, it was measured throughout, and it produced the wrong answer. This is the record of what was run, what held up, what did not, and what the run costs.

Two of these four numbers look good and mean nothing. Forget accuracy is 10% because every task is at 10%. Relapse is 0 because a task that has collapsed to chance cannot creep back. Read alongside a retain accuracy of 10%, they are symptoms, not successes. This is a concrete demonstration of the paper's own argument for reporting four numbers, and a reminder that two of them are only meaningful when the other two are healthy.

What went right

Learning works

Before the collapse, individual tasks reached accuracies in the paper's own region: task 5 at 59.8%, task 17 at 57.0%, task 19 at 56.0%, task 9 at 49.2%. The paper's whole-run retain accuracy is 55.24%. So the hypernetwork, the chunked generation and the learning objective are all doing their job.

Forgetting hits its target exactly

Every unlearn request drove its task to exactly 10.0%, first time, every time. The forget loss settles at 236,000 to 264,000 against a theoretical floor of gamma × d = 235,208, so the objective is not merely working but close to converged.

Burn-in annealing behaves as specified

100  90  81  72  65  59  53  47  43  38  34  31

Appendix C's 10% decay with a floor of 20, over twelve unlearn requests.

The instrumentation held

Per-request timing, peak memory, the four JSON files, the progress bars and the cost table all worked on the first full-scale run. Nothing had to be re-run to recover a number.

What went wrong

Forgetting destroys the retained tasks

Spill per unlearn request, in order:

15.4  162.8  59.4  48.4  13.0  63.0  2.0  4.0  0.6  0.0  0.0  0.0

The trailing zeros are not improvement. By request 15 every task sits at 10%, so there is nothing left to disturb. The paper's mean spill for this setting is 0.722; the first unlearn here, with a single task to protect, did 15.4. That is twenty times the paper's whole-run average before any long-history effect can be blamed.

The generator dies

Requests 25 to 29 are learns, and their final losses are 2.3028, 2.3027, 2.3027, 2.3026, 2.3026. That number is ln(10): the network emits identical logits for every input. After the mass unlearning it cannot learn a new task at all.

This inverts the paper's second claim. Table 3 argues that unlearning restores plasticity, 50.47% to 55.24% on Tiny ImageNet, by returning capacity. Here unlearning removed plasticity entirely. Whatever the cause, saturation alleviation cannot be tested on this code until it is fixed.

Same failure mode as the initialization bug, different cause

A loss pinned at ln(10) with accuracy at exactly 10.0 appeared earlier in the day from He initialization on the classifier, and was fixed. It has reappeared, now caused by the forget objective rather than the starting point. Worth noting as a signature: loss = 2.3026 and accuracy = 10.0 to one decimal means collapse to uniform logits, and the question is only what pushed it there.

Leading hypotheses

Untested. Listed so the next run is a decision rather than a guess.

  • Gamma too strong for this implementation. In forget the loss is gamma * noise + preserve, with no weight on the preservation term. The noise gradient acts on all 23.5M generated values through a shared trunk. Preserve resists and loses.
  • Preservation is averaged over protected tasks. total / len(protected) means per-task protection weakens as history grows. This cannot explain the first unlearn, where there is one protected task, so at most it compounds a problem that starts elsewhere.
  • Burn-in of 100 Adam steps at 1e-3 is a large move for a shared generator. The paper's scheduler is described but never specified.

The experiment that separates the first from the rest is three requests over four values of gamma, about ten minutes on an A100:

for gamma in (0.1, 0.01, 0.001, 0.0001):
    r = run_experiment(sequence=1, backbone="resnet50", epochs=5,
                       limit_requests=3, gamma=gamma, root=DATA, output=None)
    print(gamma, r["numbers"]["mean_spill"], r["history"][2]["after"])

The cost model

Fitted to the thirty measured requests. Time per optimizer step is linear in the number of protected tasks, for both actions:

learn    s/step = 0.0948 + 0.0390 * protected
forget   s/step = 0.0063 + 0.0475 * protected

Summed over sequence 1 this predicts 55.9 minutes against 55.9 measured, within 0.1%.

Two things follow. The slopes agree within 22%, so once a few tasks have been learned, the regularizer is the cost and the objective is noise around it: a forget step costs about what a learn step costs, despite touching no data. And because cost per request grows linearly with history, the cost of a whole sequence grows roughly with the square of its length. The first learn took 36 s; the eighteenth took 302 s, 8.4× more, for identical work.

Learnings

About the method

  • Retain accuracy and forget accuracy are not independent. A collapsed model scores perfectly on two of the four metrics. Always read them together.
  • The regularizer, not the objective, determines what a run costs. Any work on efficiency should start there, which is also where the paper's stated research angle about budgeting the protected set points.
  • The forget loss has a floor of gamma × d, which for ResNet50 is 235,208. A forget loss "not going down" is expected; what matters is its distance above that floor.

About the process

Every failure that reached the notebook was code that had been reasoned about and not executed: a missing importlib.invalidate_caches(), a dataset path on a network drive, a tuple unpack of a dict, a filename that only existed after one particular run. All of them reproduce in plain Python in seconds. scripts/check_guide.py now executes every code block in the guide, and that is the control that should have existed first.

What exists now

  • One package, uncle, with one Tiny ImageNet loader and one class partition.
  • Per-request timing and peak memory, written to disk as the run goes.
  • Checkpointing after every request. A killed run resumes and reproduces the history it would have had, exactly, on CPU.
  • 36 checks across three test files, plus 18 executable guide blocks.
  • A measured cost model that predicts a full sequence within 0.1%.

Open, in order

  1. The gamma probe above. Ten minutes, and it decides whether the collapse is tuning or structure.
  2. If structural: examine the balance between the noise and preservation terms in forget, including whether preservation should be summed rather than averaged over protected tasks.
  3. Only then the paper's experiments, since saturation alleviation and the metric comparisons all need a run that retains something.
  4. Compute planning for the full set of experiments and the research angle, using the cost model above rescaled to H100.
